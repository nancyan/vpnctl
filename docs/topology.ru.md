# vpnctl v0.4: генерация конфигураций (RU)

`render` — **офлайновый** генератор конфигураций Xray и фрагментов NGINX Stream. Никаких подключений к VPS и изменений на серверах.

1. Скопируйте `examples/topology.example.json` в `topology.local.json` (исключён из Git).
2. Укажите свои домены, UUID, реальные пары X25519 Reality, `short_id` и порядок `next_hop`. Ключи можно получить штатными средствами Xray (`xray x25519`), отдельно на каждом узле. Пример намеренно содержит **неработающие** значения ключей.
3. Запустите `python3 vpnctl.py --lang ru render --topology topology.local.json --output rendered`.
4. Посмотрите `rendered/<имя>/xray.json` и `nginx-stream.conf.example`. Содержимое `rendered/` содержит секреты и исключено из Git.

Поддерживаются `entry`, `relay`, `exit` и последовательная маршрутизация по `next_hop`, без циклов. Выходной узел направляет трафик через `freedom`. Предполагается, что на каждом узле **уже существует** HTTPS-сайт на `127.0.0.1:9443` с корректным сертификатом для указанного домена; REALITY направляет неподходящие подключения на него. Xray слушает **только** `127.0.0.1:3030`.

**Ограничения:** фрагмент NGINX Stream рассчитан на новый VPS и должен помещаться внутрь **существующего** блока `stream {}`. Не вставляйте его в `http {}` и не создавайте второй listener на `443`. Генератор пока не устанавливает NGINX, не выдаёт TLS-сертификаты, не конфигурирует 3x-ui и не применяет файлы на серверах. Нет автоматического failover/Observatory. Сначала проверяйте конфигурации на одноразовой тестовой VM с `xray run -test -config ...` и `nginx -t`, затем тестируйте передачу трафика.

**Безопасность:** не публикуйте `topology.local.json`, содержимое `rendered/`, UUID или приватные Reality-ключи. Для хранения используйте Vault или секретное хранилище. Генератор не сверяет соответствие публичного ключа приватному — проверьте пары перед тестом.
